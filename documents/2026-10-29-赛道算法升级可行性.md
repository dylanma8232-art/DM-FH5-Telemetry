# 赛道算法三项升级：代码级可行性与实测

日期：2026-10-29。只读摸底，未改业务代码，未提交。探针在 `/tmp/bench/algo-probe.mjs` 与 `/tmp/bench/algo-probe-2.mjs`，原始结果在 `/tmp/bench/algo-probe-result.json`、`/tmp/bench/algo-probe-2.json`。

数据：`/tmp/bench/fixture-data/tracks` 共 32 条。其中 30 条合成中心线各 2000 点且没有 `kappa`，1 条带真实曲率（`track_1793262554369`，1733 点），1 条只有 6 个点、没有中心线（`track_1793264035013`，只参加长度对比）。回放为 `/tmp/qa-smoke/forza-telemetry/data/telemetry.db` 里的 `session_smoke_replay_1`，30000 帧，`positions` 只有 `x/y/z`。

## 结论

1. **三维距离：现在不做。** 总长函数已经是三维。弯道、路书和弧长锚点仍是平面距离或按点数切分。这 32 条赛道和这 30000 帧的高程增量全是 0，长度差最大、中位、平均都是 0 米。没有坡度样本之前改路书距离，只会改代码、不改结果。
2. **连续曲率：不替换现有弯道检测。** 现有曲率已经是参数曲线的离散曲率，弯道起止点来自折线偏航，不来自曲率。换成弧长曲率后，476 个弯的起止索引偏移是 0；会漂的是弯心和半径。唯一一条真实曲率赛道的弯心移动了 302 米，半径从 33 米变成 75 米。
3. **路径预编译：有条件做，而且不要改成世界坐标。** 静态中心线可以缓存。游标、热力和编辑锚点不能缓存。管理页的平移缩放已经加在投影之后，拟合坐标里的路径在缩放时可以复用。强行改成世界坐标再做变换，会动到线宽和鼠标反算。单帧重绘的实测收益大约 0.025 毫秒，不值得为它改坐标系。

### 2. 离散曲率与弧长曲率

现状不是三点外接圆，而是对点序号做中心差分：

```text
κ = (z'x'' − x'z'') / (x'² + z'²)^(1.5)
```

位置：`centerline-processor.js:110-117`（平滑前）和 `:156-163`（平滑后，写入 `kappa/radius`）。航向在 `:145-150` 由几何中心线重算，注释写明不用遥测偏航。弯道起止点在 `track-turns.js:3-49`：抽稀容差 2 米，折点偏航超过 3 度才记弯，再按同向和距离合并。`kappa` 只在 `calculateTurnAttributes`（`track-turns.js:243` 起）里决定弯心（半径最小的点）、左右方向和半径。严重度看的是起止航向差，不看曲率。

连续曲率的对照实现：先累计平面弧长，航向取 `atan2(Δz, Δx)` 并展开，再做中心差分 `κ = −dθ/ds`。负号是为了对齐现有实现「正曲率为顺时针、右转」。重复点或步长小于 `1e-6` 米时记 0。

把两种曲率先写入点，再调用仓库里的 `detectTurnsEnhanced`（31 条可用中心线，476 个弯）：

| 项目 | 结果 |
| --- | --- |
| 起止索引不一致的弯 | 0 / 476，偏移 0 米 |
| 方向翻转，从而路书名称左右对调 | 128 / 476，全部发生在没有预存曲率的合成折线 |
| 弯心弧长偏移 | 中位 12.2 米，平均 14.0 米，95 分位 39.3 米，最大 302 米 |
| 半径差 | 中位 7 米，95 分位 12 米，最大 42 米 |
| 严重度 / 弯型被曲率单独改掉 | 没有。名称变化与方向翻转次数相同 |

唯一带预存曲率的赛道 `track_1793262554369`：重算离散曲率与档案里的 `kappa` 平均绝对误差是 0，公式核对通过。整圈 2437 米，现有检测只产出 1 个弯，索引 56 到 1673，长 2288 米，名称「左1长」，半径 33 米，转角 163.6 度。换弧长曲率后起止点和名称不变，弯心沿弧长移动 302 米，半径变为 75 米。原因是窗口几乎是整圈，最小值点对噪声极敏感，不是弧长公式整体平移了弯道。逐点 `|Δκ|` 中位只有 `5.8e-5`（约等于半径很大时的噪声），最大 0.018。

合成中心线不能代表真赛道。以第一条 2000 点样本为例，点距中位 2.90 米，离散 `|κ|` 中位 0.243（相当于半径约 4 米），弧长 `|κ|` 中位 0.060。折线锯齿让二阶差分比弧长差分更大，所以 128 次方向翻转没有外推价值。31 条上逐点 `|Δκ|` 的中位值，再取中位，是 0.206，最大可达 1.58。

回放 30000 帧更接近光滑采样：`|Δκ|` 中位 `6.0e-6`，平均 0.0024，最大 0.080。两种公式在 `|κ|>1/200` 上只有 12 个点判定不一致。但两边都有约 1210 个点 `|κ|>1`（半径小于 1 米）。原始帧即使点距和速度都正常（本样本零速帧为 0、完全重合点为 0），仍会有尖峰，不能直接拿来切弯。先按 30 米窗平滑后，以半径 80、200、500 米做迟滞分段，两种曲率都得到 318 段，起点偏移 0，终点偏移中位 0、最大 1.9 米。

用曲率阈值去对齐现有弯道边界是不可行的。真实曲率那条赛道，半径阈值 40–200 米、平滑窗 0/20/40 米，都无法覆盖那个 2288 米的单一弯（重叠不足两成，记为未匹配）。未平滑时离散曲率在半径 200 米阈值下切出 22 段，弧长曲率也是 22 段，对上的 19 段起点偏移中位 0、最大 127 米。平滑 20 米后两边都变成 0 段，因为这条赛道的曲率峰值只有 0.030（半径约 33 米），平滑后过不了阈值。现有弯道边界本来就不是曲率阈值切出来的。

连续曲率并不更慢。成本在弯心、半径和噪声尖峰，不在耗时。

风险：只替换 `kappa` 公式不会移动 `startIdx/endIdx`，但会改弯心坐标、`radius`、左右方向，从而改路书名称和刹车参考点附近的取样。合成折线上方向翻转比例是 27%。存盘格式不用加字段，但已生成的路书内容会变。在现有检测会把整圈收成一个弯的赛道上，弯心可以移动数百米。

| 锚点和弯号 | 同文件 `:951-1055` | 动态 | 圆和文字，不适合放进线路径 |

会话地图的绘制效果依赖 `cursorPoint`（`TrackMaps.jsx:285`）。回放游标每动一帧，静态中心线都会被清空并重放。管理页 `drawCanvas` 依赖 `transform`（`TrackManagerPage.jsx:1127` 附近），平移缩放会整图重画。

缓存能不能跨缩放复用，两边不一样：

- 管理页先把点投到「适配画布」的坐标，再 `ctx.translate` + `ctx.scale`（约 `:809-812`）。用户的平移缩放不改变路径坐标。拟合坐标里的 `Path2D` 可以跨缩放复用。线宽、虚线和字号现在除以 `transform.scale`，这些必须留在每次描边时设置，不能烤进路径。
- 会话地图没有这层用户变换。放大某个弯时，投影用的包围盒直接改掉（约 `:100-116`），屏幕坐标路径必须重建。热力和游标每次都要重建。
- 失效条件：中心线或边线点列变化、闭环标志变化、画布尺寸变化、会话地图的包围盒或降采样步长变化、正在编辑的弯道索引变化。管理页仅平移缩放时，几何路径不必失效。

不建议改成「世界坐标 Path2D + `setTransform`」。现有线宽是 `1.5 / transform.scale` 或 `12 * sc`，鼠标反算放在 `mapContextRef` 的适配坐标系里。把适配比例再乘进矩阵后，线宽、虚线、锚点半径和拾取必须一起改，否则线会变粗或点不中。这是行为风险，不是性能前提。管理页要复用路径，保持现在的「先适配、后缩放」即可。

无头 Chrome 156.0.8078.48 实测，900×600 画布，2000 个点，每次描边后读回 1 个像素，避免把绘制优化掉：

| 做法 | 每次 |
| --- | ---: |
| 重放 2000 个 `lineTo` 再描边 | 0.111 毫秒（300 次） |
| 已建好的 `Path2D` 只描边 | 0.086 毫秒（300 次） |
| 每次重建路径并描边 | 0.103 毫秒（200 次） |
| 降到 500 点再重放 | 0.059 毫秒（300 次） |

不读回像素时，2000 点只录制命令大约 0.022 毫秒，热力 58 段大约 0.005 毫秒。栅格化占掉大部分时间，`Path2D` 只省掉录制命令的大约 0.025 毫秒。值得做的是游标移动时不要清掉并重画静态线，而不是把坐标系改掉。

## 风险汇总

- 这批数据高程增量为 0。把路书改成三维距离，现在不会改变任何存盘数字；一旦赛道有坡，`s` 和「到下一弯」会变，旧档案要重算。
- 扇区不看长度。改距离不能顺手「修正」扇区。
- 抽稀容差已经含 `y`，弯道转角不含 `y`。以后有坡时，这两处会不一致，需要单独定规则，不能只改总长。
- 替换曲率不移动弯道起止索引，但会改弯心、半径和左右方向，路书文本会变。
- 原始 30000 帧有千级曲率尖峰。连续曲率不比离散曲率更稳，必须先平滑或重采样。
- `Path2D` 若改世界坐标，线宽和拾取会一起错。热力、游标、编辑锚点不能缓存。

## 建议的施工顺序

1. 不做连续曲率替换，也不要把弯道检测改成曲率阈值。现有起止点规则保持不动。若以后要修「整圈被收成一个弯」，那是弯道合并规则的问题，不是曲率公式的问题，且会直接改路书，需单独开任务。
2. 画线只做小改：会话地图把静态中心线和动态游标拆开，静态层用拟合坐标 `Path2D`；管理页同样只缓存底色、边线和中心线。不改 `setTransform` 方案，不缓存热力和锚点。
3. 三维距离先补一条高程不为 0 的回归夹具，再决定是否把 `s`、弯长和路书间距改成三维。在那之前不要改。总长函数已经是三维，扇区继续按点数切。

### 4.3 TTS 链路与吞字防护

- 链路：浏览器内置 `window.speechSynthesis`（**离线，走系统语音**），无云端调用；设置面板可选声优与语速（`SettingsPanel.jsx:89-90, 558-578`）。
- 队列：`client/src/utils/speechQueue.js`（200 行，`f230288` 新增）。优先级 3/2/1（极高/弯道/普通）；串行播完、队列容量 3、满则丢最旧；极高优先级可打断并清空队列。
- 吞字防护：1.5 秒同句防刷（`speak()` 内），但 `_playNext()` 队列接续直走 `_enqueueOrSpeak` 绕过防刷，修掉了「接续播报被防刷误吞」的坑；`onend` 强引用挂全局防 GC 丢失；超时自愈触发 `_playNext`。
- 结论：三件（动态提前量、复合弯一句、防吞字队列）均已落地且口径符合闸门；唯一常数级偏差（2.5 vs 3.5）已纠偏。
