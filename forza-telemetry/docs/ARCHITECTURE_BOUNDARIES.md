# 架构与开发规范

本规范用于保证新增功能不会重新引入重复请求、超大页面和状态分叉。功能正确性优先于压缩行数；重构必须保持接口、数据格式和交互时序。

## 模块边界

- `client/src/components/pages/` 仅组合页面、局部视图状态和既有 Hook；独立画布、表格、弹窗和展示区应放入对应功能目录。
- `client/src/hooks/` 负责异步数据、订阅、清理和跨组件业务状态；展示组件不得自行维护全局业务状态。
- 浏览器 HTTP 请求只能定义在 `client/src/services/api.js`。JSON、二进制、下载等不同响应形式必须提供具名 API 方法，页面和 Hook 不得拼接接口地址。
- `server/src/index.js` 仅负责启动、停止和依赖组装。路由负责输入校验与 HTTP 编排；服务负责业务规则；存储层是 JSON、压缩文件和 SQLite 的唯一读写边界。
- `stateManager` 是运行时共享状态的唯一来源。不得在模块顶层保存可变状态的副本；刷新状态时必须原地更新对象，保留已有引用。
- 改装目录优先使用车型专属档案；缺少专属资料时回退到该项目的通用候选；仅当档案明确验证游戏内不存在时隐藏。没有可靠通用枚举的项目不得伪造候选。

## 文件与变更规模

- 新增生产文件目标不超过 400 行；超过 600 行必须在同一功能目录拆出纯展示组件、工具函数或领域 Hook。
- 不允许为了拆分而改变 API、遥测节流、录制状态机、赛道几何或手动调校行为。
- 不做 React、Vite、Express 主版本升级与业务重构的混合提交。

## 测试与验证

- 修改前端 `src/` 后必须运行 `npm run build:client`；浏览器验收只能使用 `http://localhost:9188`。
- 提交前必须运行 `npm run verify`、`npm run lint:dead` 和 `git diff --check`。
- 新增 API 方法必须在 `client/test/` 覆盖 URL、HTTP 方法、请求体和错误语义。
- 修改服务端共享状态、存储或纯业务规则时，必须在 `server/test/` 增加隔离测试。新增路由前先补成功与失败响应的契约测试。

## 禁止事项

- 禁止恢复 Vite 开发服务器、预览服务器或任何非 9188 的页面验证端口。
- 禁止在组件或 Hook 中新增裸 `fetch('/api/...')`。
- 禁止路由直接读写文件，或绕过存储层修改运行时数据。
- 禁止将历史备份文件（例如 `.bak`）放入 `src/`。
