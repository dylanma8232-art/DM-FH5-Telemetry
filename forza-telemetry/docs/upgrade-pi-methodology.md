# 改装配件 PI 方法论

## 目标

手动改装时，页面的配件 PI 与游戏 PI 应尽量接近；对已校准的底盘与传动配件，整车累计误差目标为约 5～8 PI。不得要求用户逐辆车重复实测。

## 数据边界

当前模型以 12 辆游戏内实测车辆作为训练样本。它们是跨车型训练数据，不是只服务于这 12 辆车的查表数据。

实测覆盖较好的范围：轮胎宽度、轮距、悬挂、防倾杆、刹车、减重、差速器、变速箱、传动轴。

发动机置换、增压、进气、节气门、排气、凸轮轴、轮胎配方、空力和轮毂等未获得足量同类实测时，只能使用低置信度物理公式，不能宣称误差在 5～8 PI 内。

## 单个配件 PI 的取值顺序

1. 相同车辆、相同配件的游戏实测值。
2. 统一跨车型模型：使用原厂 PI、车重、驱动形式训练；模型通过按车辆留一验证选择。
3. 物理公式估算，并标记为预测。

车辆 ID 只能用于命中已有实测，不能作为新车预测的主特征。

## 统一模型规则

- 样本按车型计数，不能把同一辆车的多项配件记录当成多辆独立车辆。
- 少于 12 辆车型：只允许全局均值或按驱动形式的收缩均值。
- 12～19 辆车型：才允许原厂 PI + 车重的简单回归。
- 20 辆车型以上：才允许加入驱动形式的多特征回归。
- 模型选择必须采用按车辆留一验证；不得只看训练集误差。
- 对外误差带使用留一验证误差，不能使用训练内误差。

## 整车总 PI

```text
总 PI = 原厂 PI + 每个当前已选配件的 PI
```

同一槽位只取当前选择。例如减重选择赛车级时，不叠加街车级和跑车级。

若命中一套已实测的完整构型，则完整构型游戏实测 PI 优先。

## 高方差项

“跑车级减重”在当前样本中为 +8 到 +38 PI，无法由原厂 PI、车重和驱动形式稳定解释。它必须标记为高方差预测：

- 手动模式可以显示预测区间。
- 不得显示为精确 PI。
- AI 不得用它进行目标 PI 的精确卡位。

## 配件可用性与 PI 必须分离

配件是否存在，不等于它的 PI 是否已校准。

可用性优先级：

```text
车辆专属配置 > 已确认不可用 > 已确认可用 > 规则推断 > 通用模板 > 未知
```

- 已确认不可用：隐藏，AI 禁用。
- 车辆专属：使用车辆文件的真实选项。
- 规则推断：可在手动模式显示为推断，AI 需谨慎。
- 未知：不得伪装成游戏可用选项，也不得进入 AI 候选。

轮胎宽度、轮距和轮毂尺寸属于车辆专属离散选项，不能因为其它车有“加宽一级”就假设所有车都有。

## AI 约束

AI 只能负责在服务端给出的候选里做性能取舍，不能创造配件 ID 或自行编造 PI。

AI 方案必须满足：

```text
预测总 PI + 误差上限 <= 目标 PI
```

AI 回填前必须经过服务端的车辆可用性与 PI 校验。缺少可信 PI 的配件不得被 AI 当成精确配件使用。

## 修改时的必做验证

1. 运行服务端测试。
2. 修改前端后运行客户端生产构建。
3. 运行 CodeGraph 同步和 `npm run build:map`。
4. 任何新实测数据必须记录其测量方式；不得将整车误差平均分摊给单个配件。
