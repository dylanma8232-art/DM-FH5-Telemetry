# 赛道与路书方法论

> 面向后续维护 Agent 的约束文档。赛道数据来自比赛遥测；系统没有游戏道路边界或官方赛道网格，因此不得把任意单圈驾驶轨迹称为“绝对真实赛道几何”。目标是在自然比赛走线中稳定提取可编辑、可播报的赛道参考线。

## 一、不可改变的原则

1. **RDP 决定宏观弯道结构。** `detectTurnsEnhanced()` 先用 RDP 消除高频微操、反打和采样噪声，再按方向和距离合并折点。不要以连续曲率阈值完全替换 RDP。
2. **拟合只稳定局部，不强制圆化所有弯。** `reconstructTrackGeometry()` 对适合的弯段做圆弧拟合；复合弯、渐开弯、直角弯或拟合不可靠的段落必须保留原中心线。
3. **地图几何与驾驶建议分层。** 中心线、弯道方向、1–6 级别、入口/顶点/出口由赛道几何确定；速度、刹车点、档位、路面信息由多条遥测轨迹统计补充。
4. **每场比赛都要生成候选地图，但不能自动覆盖正式地图或编辑路书。** 候选必须可见、可比较、可人工采用。
5. **路书显示和语音必须使用同一份前方弯道与同一 WRC 1–6 字段。** 语音请求被 TTS 拒绝、抢占或忙碌时，不得标记为“已播报”。

## 二、录制到正式地图的流程

```text
比赛遥测
  → 保存原始轨迹
  → 补密、传送/异常片段切断、主线偏离过滤
  → 多轨迹合并为中心线
  → RDP 宏观分弯与同向合并
  → 分段拟合稳定几何
  → 生成候选中心线、候选弯道、候选路书
  → 赛道管理页叠加显示正式地图与候选地图
  → 用户采用候选地图
  → 更新正式中心线、自动路书、扇区与参考几何版本
```

### 正式地图

- `centerline`、`turns`、`routeBook`、`referenceGeometry` 是当前正式版本。
- 路书编辑始终编辑正式版本。
- 新比赛不得直接重写这些字段。

### 候选地图

- 每次赛道模式完赛，由 `save-worker.js` 用最新轨迹集合构建 `geometryCandidate`。
- 候选包含 `centerline`、`turns`、`routeBook`、`sectors`、长度、闭环状态和生成时间。
- `TrackManagerPage.jsx` 以紫色虚线叠加候选；页面展示正式/候选长度和弯道数，并提供“采用候选地图”。
- `POST /api/tracks/:id/adopt-candidate` 是唯一将候选提升为正式几何的接口。

## 三、弯道与路书语义

- 弯道方向只允许 `left` / `right`。
- WRC 等级统一使用 `turn.severity` 的 `1–6` 值：1 为最急/发卡，6 为最缓微弯。
- 路书必须保存 `startS`、`apexS`、`endS` 弧长锚点；索引会随重采样变化，不能把数组索引作为唯一长期锚点。
- `customNote` 是用户编辑数据，重建、候选采用、合并时必须尽量按弯道空间位置映射保留。
- 路书语音使用与 HUD 相同的 `getWrcLabel()` 和“几何前方下一个弯”结果；不可单独按路书数组首项播报。

## 四、质量与保护规则

- 环道不只依赖圈数：必须同时具备圈证据与中心线首尾物理距离足够近。
- 多条轨迹中大多数偏离主骨架时，残留少数片段不能覆盖正式地图。
- 历史全量重建前必须创建可恢复备份；未经逐赛道验证，不得把新识别器批量提升为正式地图。
- 赛道管理的“删除”会删除赛道详情、索引和关联比赛摘要/高精遥测；它不是全量级联清理，低清文件及部分数据库数据可能仍需专门处理。
